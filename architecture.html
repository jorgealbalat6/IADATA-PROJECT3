Inside Airbnb
insideairbnb.com · Open Data
FUENTE EXTERNA
¿Qué es?
Dataset público con snapshots periódicos de los pisos Airbnb en Barcelona. Contiene información de listings, disponibilidad por día (calendar) y reseñas.
Snapshots disponibles
2025-06-12 2025-09-14
Archivos descargados
listings.csv.gz — datos del piso (precio, habitaciones, reviews...)
calendar.csv.gz — disponibilidad diaria (hasta 365 días por piso)
URL base
https://data.insideairbnb.com/ spain/catalonia/barcelona/ {SNAPSHOT_DATE}/data/listings.csv.gz

ingesta-airbnb
ingesta/historicos/main.py
CLOUD RUN
Lógica principal
1
find_consistent_ids() — Descarga todos los snapshots y calcula la intersección de IDs con precio. Solo pisos presentes en todos los snapshots.
2
transform_listings() — Convierte precio de "$1,200.00" → 1200.0, instant_bookable "t"/"f" → boolean.
3
load_to_bigquery() — Carga a airbnb_raw.listings y airbnb_raw.calendar con WRITE_APPEND.
Query params HTTP
?force=true ?start_date= ?end_date=
Recursos Terraform
Memory: 4 GiB (archivos .gz grandes). Service account: sa-ingesta-airbnb con roles bigquery.dataEditor + bigquery.jobUser.

ingesta-events
ingesta/eventos/main.py
CLOUD RUN
Lógica principal
1
fetch_events() — Paginación automática (limit=200). Itera mientras data["next"] no sea None.
2
transform_events() — Extrae coordenadas (PredictHQ devuelve [lon, lat]), calcula duración en días.
3
load_to_bigquery() — Carga a airbnb_features.events. Elimina duplicados por event_id si force=true.
Modos de ejecución
/? → próximos 30 días /?mode=historical → desde 2025-06-01 /?start_date=&end_date= → rango personalizado /?force=true → re-ingesta

tiempo (ingesta meteo)
ingesta/tiempo/main.py
CLOUD RUN
Dos modos
H
Histórico — Datos reales desde Open-Meteo Archive API. Borra y reemplaza las fechas existentes.
F
Forecast — Previsión 14 días. Solo borra forecast previo de esas fechas (no toca el histórico).
Estrategia de upsert
delete_existing_dates() — Si source=historical borra todas las filas de esas fechas. Si source=forecast, solo borra forecast para no sobreescribir datos reales validados.
Scheduler
Forecast: todos los días a las 2:00 AM
Histórico: cada lunes a las 2:00 AM

ingesta/festivos/main.py
CLOUD RUN
Lógica

check_already_ingested(year) — Evita duplicados consultando BigQuery antes de ingestar.

stg_listings
dbt · Staging · Materializado como TABLE
DBT
Transformación clave
Usa QUALIFY ROW_NUMBER() para quedarse solo con el snapshot más reciente de cada listing, eliminando duplicados entre snapshots.
QUALIFY row_number() OVER ( PARTITION BY id ORDER BY snapshot_date DESC ) = 1
Renombrado
id → listing_id, price → listing_price
🧹
stg_calendar
dbt · Staging · Materializado como TABLE
DBT
Feature generada
Genera la variable objetivo del modelo ML:
CASE WHEN available = false THEN 1 ELSE 0 END AS is_occupied
Lógica
En Airbnb, available=false significa que el piso no está disponible, es decir, está ocupado (reservado o bloqueado).
🔗
int_calendar
dbt · Intermediate · Materializado como VIEW
DBT
Features temporales añadidas
day_of_weekmonth yearweek_of_year is_weekend
Feature especial
days_to_next_holiday — Subconsulta que busca el festivo más próximo futuro para cada fila. Feature muy valiosa: los precios suben días antes de un festivo.
date_diff( (SELECT MIN(h.date) FROM stg_holidays h WHERE h.date >= calendar.date), date, day ) AS days_to_next_holiday

mart_occupancy_features
dbt · Marts · Tabla ML-ready MAESTRA
DBT MART
¿Qué es?
Tabla final que une todas las fuentes con JOINs sobre la fecha. Una fila = un listing en un día específico.
Joins realizados
→
calendar LEFT JOIN listings ON listing_id
→
LEFT JOIN weather ON date
→
LEFT JOIN int_events_daily ON date
→
LEFT JOIN holidays ON date
Filtro de fecha
WHERE c.date BETWEEN '2025-06-12' AND '2026-04-30'
Variable objetivo
is_occupied (0/1) — Lo que predice el modelo ML.
Optimización BigQuery
Particionada por date. Clusterizada por neighbourhood_cleansed y room_type.
